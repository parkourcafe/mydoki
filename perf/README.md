# Бюджет производительности apply-страницы (T7)

Публичная страница отклика `/apply/[slug]` — главный вход кандидата. Её часто
открывают с дешёвых Android-телефонов по медленному мобильному интернету, часто
одной рукой в шумной обстановке. Поэтому у неё есть **бюджет производительности**,
который защищён автоматикой.

## Что гарантируем

| Метрика | Бюджет | Где проверяется |
|---|---|---|
| First Load JS роута `/apply/[slug]` | **≤ 150 КБ gzip** | `npm run perf:budget` (детерминированно, в CI на каждый PR) |
| Performance (Lighthouse, mobile) | **≥ 0.90** | LHCI против preview-URL |
| Largest Contentful Paint | **≤ 2500 мс** | LHCI |
| Cumulative Layout Shift | **≤ 0.1** | LHCI |
| Total Blocking Time | ≤ 300 мс (warn) | LHCI |

## Как держим вес

- **Шапка вакансии — чистый Server Component** (`page.tsx`): никакого JS у
  кандидата за неё не платится. Аватар — CSS-кружок с инициалами, без картинки.
- **Форма — единственный клиентский остров** (`ApplyForm.tsx`).
- **`@supabase/supabase-js` (~50 КБ gzip) грузится лениво** — динамическим
  импортом внутри `handleSubmit`, только когда пользователь реально отправляет
  отклик. В First Load его нет.
- **Сжатие фото** (`browser-image-compression`, `heic2any`) — ленивые
  динамические импорты в `lib/compressImage.ts`, вне начального бандла.
- **Turnstile** «взводится» только после первого касания формы; его контейнер
  резервирует высоту `min-h-[65px]` заранее — виджет появляется без сдвига
  layout (защита от CLS). Скрипт Cloudflare не участвует в LCP.
- **Yandex Metrika** грузится со `strategy="lazyOnload"` — после простоя, не
  конкурирует с отрисовкой контента.
- **QR-библиотека** (`qrcode`) используется только в кабинете работодателя
  (`DistributionCoach`) и в бандл apply-страницы не попадает.

## Как проверить локально

```bash
# 1. Детерминированный бюджет веса (после сборки):
npm run build
npm run perf:budget

# 2. Из чего состоит бандл (визуальный анализ):
npm run analyze
# откроет .next/analyze/*.html — ищите тяжёлые модули в чанках apply-роута

# 3. Lighthouse против локального прод-сервера:
npm run build && npm start &
npx @lhci/cli@0.14.x autorun --collect.url=http://localhost:3000/apply/<slug-активной-вакансии>
```

Для LHCI нужна **активная вакансия** с валидным slug (страница неактивной
вакансии отдаёт заглушку и метрики не репрезентативны).

## LHCI в CI

Job `lighthouse` в `.github/workflows/perf.yml` запускается только если в
настройках репозитория задана переменная `LHCI_URL` (Settings → Secrets and
variables → Actions → Variables). Укажите туда preview-URL Vercel со страницей
отклика активной тестовой вакансии, например
`https://<preview>.vercel.app/apply/<seed-slug>`. Без переменной job тихо
пропускается, а обязательный чек веса (`bundle-budget`) работает всегда.

## Протокол проверки на реальном устройстве

Синтетика (LHCI) — необходимый минимум, но перед крупными изменениями apply-
страницы прогоняйте ручной тест на настоящем телефоне:

1. **Устройство**: реальный бюджетный/средний Android (напр. что-то уровня
   Redmi/Samsung A-серии), а не флагман. Именно такие у целевой аудитории.
2. **Сеть**: включите троттлинг «Fast 4G» или «Slow 4G» в Chrome DevTools
   (Remote Debugging по USB) либо тестируйте на реальном мобильном интернете,
   не на Wi-Fi.
3. **Холодная загрузка**: очистите кеш (DevTools → Network → Disable cache,
   или режим инкогнито), откройте ссылку отклика с нуля.
4. **Что замеряем**:
   - **LCP** — заголовок вакансии виден ≤ 2.5 c.
   - **CLS** — при появлении Turnstile и статусов загрузки файлов ничего не
     «прыгает». Особенно проверьте момент первого касания формы (взвод
     Turnstile) и выбор файла.
   - **TBT/отзывчивость** — поля ввода реагируют мгновенно, без залипаний.
   - **Полный сценарий**: имя → WhatsApp → выбор фото (проверьте, что HEIC с
     iPhone конвертируется и сжимается) → отправка. Отправка не должна
     «висеть» дольше пары секунд на 4G.
5. **Быстрый внешний прогон**: [PageSpeed Insights](https://pagespeed.web.dev/)
   по публичному URL страницы отклика — даёт полевые (CrUX) и лабораторные
   метрики без локальной настройки.

Если ручной прогон расходится с синтетикой — верьте реальному устройству и
чините First Load / CLS до зелёных значений.

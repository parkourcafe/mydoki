# Публикация в Google Play через TWA (T10)

doki.help — это PWA, а Google Play принимает её как приложение через **TWA**
(Trusted Web Activity): тонкую Android-обёртку, которая открывает сайт в
полноэкранном режиме без адресной строки. Никакого второго кода — приложение
это и есть doki.help.

## Что уже готово в коде ✅
- **Манифест** `app/manifest.ts` — `display: standalone`, иконки 192/512 (+maskable), `theme_color`, `start_url: /id`, `lang: id`.
- **Иконки** генерируются роутами `app/icon-192`, `app/icon-512`, `apple-icon`.
- **Service worker** `public/sw.js` (пуши T9 переносятся в TWA без изменений).
- **Digital Asset Links** — роут `/.well-known/assetlinks.json`, значения из env (см. ниже).

> **Стартовый экран — индонезийский лендинг `/id`, не кабинет.** Манифест
> переориентирован на индонезийский рынок (`name`, `description`, `lang` — на BI).
> Это значит, что приложение из Play открывается на публичной странице, а не на
> входе в хранилище. Если для сторовой версии это неверно, менять надо
> `app/manifest.ts`, а не Bubblewrap: TWA берёт `start_url` из манифеста.

## Перед сборкой — решение, которое нельзя переиграть

**Package name в Google Play неизменяем навсегда.** После первой загрузки `.aab`
пакет нельзя переименовать — только заводить новое приложение и терять установки
и отзывы. Поэтому имя фиксируется письменно ДО первого `bubblewrap init`.

Варианты:
- **`help.doki.app`** — то же, что Bundle ID iOS-обёртки (`capacitor.config.ts`).
  Пространства имён Apple и Android независимы, конфликта нет; совпадение упрощает
  диплинки, аналитику и разговор с обеими консолями. **Рекомендую этот.**
- **`help.doki.twa`** — исторический вариант из первой версии этого документа.
  Слово `twa` в публичном идентификаторе описывает нашу технологию, а не продукт,
  и останется там навсегда.

## Что нужно сделать (твоя часть)

### 1. Собрать TWA через Bubblewrap
На своём компьютере (нужен Node + JDK):
```bash
npm i -g @bubblewrap/cli
bubblewrap init --manifest https://www.doki.help/manifest.webmanifest
# package name — из решения выше; имя и цвета подтягиваются из манифеста
bubblewrap build
```
На выходе: `app-release-signed.aab` (для загрузки в Play) и keystore с ключом подписи.

### 2. Взять SHA-256 отпечаток(ки)
```bash
# отпечаток твоего upload-ключа:
keytool -list -v -keystore android.keystore -alias android | grep SHA256
```
Позже, когда включишь **Play App Signing**, Google покажет **второй** отпечаток
(ключ подписи Google) в Play Console → Setup → App integrity. **Нужны оба.**

### 3. Прописать env в Vercel-проекте mydoki
Settings → Environment Variables:

| Переменная | Значение |
|---|---|
| `TWA_PACKAGE_NAME` | package name из решения выше (тот же, что в Bubblewrap) |
| `TWA_SHA256_CERT_FINGERPRINTS` | оба отпечатка через запятую: `AA:BB:…,CC:DD:…` |

→ **Redeploy**. Проверь, что открывается `https://www.doki.help/.well-known/assetlinks.json`
и в нём твой package + отпечатки (а не пустой `[]`).

Быстрая проверка связки: [Statement List Tester](https://developers.google.com/digital-asset-links/tools/generator)
— вставь `https://www.doki.help` и package name → должно быть «success».

### 4. Загрузить в Play Console
1. Play Console → Create app → залей `.aab`.
2. Заполни листинг (описание, иконка 512, скриншоты телефона, категория, политика конфиденциальности → ссылка `https://www.doki.help/privacy`).
3. Внутреннее тестирование → добавь свой аккаунт → установи → проверь, что **адресной строки нет** (значит assetlinks сошёлся).
4. Если сверху видно URL-бар — assetlinks не прошёл: перепроверь env-отпечатки и что оба ключа добавлены.

### 5. Closed testing — самый длинный участок пути

Internal testing (шаг 4) production-доступа **не даёт**. Между ним и публикацией
стоит отдельный этап, который у нового аккаунта занимает минимум две недели:
**12 тестировщиков, непрерывно 14 дней**, после чего подаётся заявка на
production access. Требование действует для **личных** аккаунтов разработчика,
созданных после 13.11.2023.

**Проверь тип аккаунта до того, как закладывать две недели.** Организационные
аккаунты, верифицированные по D-U-N-S, от closed testing **освобождены**. Если
Play-аккаунт оформляется на юрлицо с D-U-N-S — эти две недели из плана исчезают.
Это решение стоит принять до регистрации аккаунта, а не после.

Если этап всё-таки нужен:
- 12 живых людей на реальных Android-устройствах с настоящими Google-аккаунтами;
  эмуляторы, боты и дубли аккаунтов не засчитываются;
- с апреля 2026 Google отклоняет заявки за формальное участие — тестировщики
  должны реально открывать приложение и ходить по экранам, а не просто числиться;
- отсчёт 14 дней непрерывный: выпадение участников ниже 12 сбрасывает прогресс.

## Частые грабли
- **Адресная строка не исчезает** → отпечаток в `assetlinks.json` не совпадает с ключом, которым реально подписан AAB. После включения Play App Signing добавь и отпечаток Google.
- **`assetlinks.json` отдаёт `[]`** → env не заданы или не было redeploy. Это ожидаемое состояние до публикации, но перед тестом связки его надо снять.
- **Стартовый экран не тот, что ждали** → `start_url` берётся из `app/manifest.ts` (сейчас `/id`), а не из Bubblewrap. Менять в коде.
- **Обновления контента** не требуют новой версии в Play — TWA грузит живой сайт. Новый AAB нужен только при смене иконки/имени/пакета.

## Мини-чек-лист запуска
- [ ] Package name зафиксирован письменно (неизменяем после первой загрузки)
- [ ] Тип Play-аккаунта известен: личный (нужен closed testing) или организационный с D-U-N-S (не нужен)
- [ ] `bubblewrap build` → `.aab` собран
- [ ] SHA-256 upload-ключа получен
- [ ] `TWA_PACKAGE_NAME` + `TWA_SHA256_CERT_FINGERPRINTS` в Vercel, redeploy
- [ ] `/.well-known/assetlinks.json` отдаёт package + отпечатки
- [ ] Statement List Tester = success
- [ ] `.aab` в Play Console, internal testing без адресной строки
- [ ] После Play App Signing — добавить второй отпечаток Google
- [ ] Closed testing 12×14 пройден (если аккаунт личный) → заявка на production access

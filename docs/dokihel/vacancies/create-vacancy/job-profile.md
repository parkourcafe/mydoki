# Профиль должности при создании вакансии

> Раздел доки: **Вакансии → Создание вакансии → Профиль должности**
> Slug: `job-profile` · Внутренний объект: `JobProfile`
> Код в продукте: мастер `app/employer/vacancies/new/WizardIntake.tsx`,
> сборка черновика `lib/vacancyWizard.ts`, шаблоны ролей `lib/roleTemplates.ts`,
> AI-черновик `POST /api/employer/vacancy-draft`.

**Профиль должности** — это структурированное описание роли, на основе которого
Doki.hel создаёт вакансию, требования, обязанности, условия работы, вопросы для
интервью и критерии оценки кандидатов.

Doki.hel создаёт вакансию не только из свободного описания, а из
структурированного профиля должности: требований к входу, необходимых знаний,
рабочих действий и условий работы.

## Термины

| Что | Значение |
|---|---|
| **Профиль должности** | Основной термин в интерфейсе и доке |
| `JobProfile` | Внутреннее имя объекта |
| Вакансия | Итоговый **публичный** текст для отклика |

Почему не просто «вакансия»? Вакансия — это итоговый текст для публикации.
Профиль должности — это структурированные данные, из которых Doki.hel собирает
вакансию, требования, обязанности, условия и вопросы интервью. Профиль должности
**не является публичной вакансией**: это внутренняя модель роли, из которой
создаётся финальная вакансия.

> Мы не называем это «ONET-анкетой» и не говорим об «интеграции O\*NET».
> Пользователю не нужно знать, что под капотом лежит методология
> американского справочника труда. Наружу — только «профиль должности».

## Из чего состоит профиль должности

1. Базовая информация
2. Входные требования
3. Требуемые знания
4. Рабочие действия
5. Контекст работы
6. Сгенерированная вакансия

## Как Doki.hel использует профиль

- формирует текст вакансии;
- выделяет **must-have** и **nice-to-have** требования;
- собирает обязанности;
- описывает условия работы;
- предлагает вопросы для интервью;
- создаёт критерии скоринга кандидатов.

## Что берём из методологии O\*NET

Берём **методологию и словарь**, а не внешний сервис. Из справочника берём
4 блока.

| # | Блок | Источник в O\*NET | Куда идёт в вакансии |
|---|---|---|---|
| 1 | Входные требования (`EntryRequirements`) | Education and Training | Требования к кандидату |
| 2 | Требуемые знания (`KnowledgeRequirements`) | Knowledge Questionnaire | Необходимые знания |
| 3 | Рабочие действия (`WorkActivities`) | Generalized Work Activities | Обязанности |
| 4 | Контекст работы (`WorkContext`) | Work Context Questionnaire | Условия работы |

### 1. Входные требования — `EntryRequirements`

Источник: *Education and Training*. Идёт в блок вакансии **«Требования к
кандидату»**. Отвечает на вопрос: какое образование, опыт, обучение,
сертификация и apprenticeship нужны человеку, которого нанимают на эту работу.

Берём поля:

```text
education_level
experience_required
employer_training_required
on_the_job_training_required
certification_required
apprenticeship_required
```

Как показываем в интерфейсе:

```text
Какой опыт нужен кандидату?
Какое образование обязательно?
Нужны ли сертификаты или лицензии?
Сколько времени потребуется на ввод в должность?
```

### 2. Требуемые знания — `KnowledgeRequirements`

Источник: *Knowledge Questionnaire*. Идёт в блок вакансии **«Необходимые
знания»**. В O\*NET знание оценивается в два шага: сначала важность, затем —
если знание важно — уровень экспертизы от 1 до 7.

Берём саму идею:

```text
knowledge_area
importance
required_level
must_have / nice_to_have
```

Как показываем: **не** выкладываем 33 знания подряд — это неуважение к
пользователю. Показываем адаптивно, укрупнёнными областями:

```text
Какие знания нужны для этой должности?
[ ] Управление и администрирование
[ ] Продажи и маркетинг
[ ] Работа с клиентами
[ ] HR и подбор персонала
[ ] Компьютеры и ПО
[ ] Финансы и учёт
[ ] Право и регулирование
[ ] Обучение и наставничество
[ ] Технические знания
```

Затем по выбранным — уровень:

```text
- базовый
- средний
- продвинутый
- экспертный
```

### 3. Рабочие действия — `WorkActivities`

Источник: *Generalized Work Activities*. Идёт в блок вакансии **«Обязанности»**.
В O\*NET каждая активность оценивается по важности, а если важна — ещё и по
уровню сложности.

Берём:

```text
activity_type
importance
complexity
is_core_responsibility
```

Как показываем: группами, не простынёй из 41 пункта.

```text
Какие задачи будут основными?
[ ] Искать и собирать информацию
[ ] Анализировать данные
[ ] Принимать решения и решать проблемы
[ ] Планировать и расставлять приоритеты
[ ] Работать с документами
[ ] Общаться с командой
[ ] Общаться с клиентами или внешними сторонами
[ ] Обучать или наставлять других
[ ] Координировать работу других людей
[ ] Управлять ресурсами или бюджетом
[ ] Работать с техникой, оборудованием или ПО
```

Из этого Doki.hel генерирует обязанности:

```text
- Собирать и анализировать информацию для принятия решений.
- Вести рабочую документацию и поддерживать актуальность данных.
- Взаимодействовать с внутренними командами и внешними участниками процесса.
```

### 4. Контекст работы — `WorkContext`

Источник: *Work Context Questionnaire*. Идёт в блоки вакансии: **Условия
работы**, **Формат взаимодействия**, **Уровень ответственности**, **График**,
а также **Риски и физические условия** — если применимо.

Берём **обязательно**:

```text
communication_frequency
contact_with_people
teamwork_level
customer_contact
conflict_frequency
decision_autonomy
task_priority_autonomy
mistake_criticality
decision_impact
accuracy_importance
deadline_frequency
schedule_type
weekly_hours
```

Берём **условно** — только если роль физическая, производственная, медицинская,
складская, полевая или транспортная:

```text
noise_exposure
temperature_exposure
contaminants_exposure
hazardous_equipment
hazardous_conditions
protective_equipment
standing_walking_sitting
repetitive_motion
physical_closeness
```

Как показываем для офисной роли:

```text
Как часто человек общается с другими?
Есть ли внешние клиенты?
Насколько самостоятельные решения он принимает?
Насколько критичны ошибки?
Как часто есть жёсткие дедлайны?
Какой график и сколько часов в неделю?
```

Дополнительно для склада / производства / медицины / транспорта:

```text
Есть ли шум, жара, холод, загрязнения?
Нужно ли защитное оборудование?
Есть ли работа с опасным оборудованием?
Сколько времени человек стоит, ходит, сидит?
```

## Что НЕ берём

- **Questionnaire Covers (обложки анкет)** — не используем. В логике продукта это
  мусорный слой (названия анкет и место под логотип). Может пригодиться позже
  для красивого PDF-отчёта «Профиль должности», но в MVP не нужно.
- **Сырой текст анкет и все вопросы подряд** — не показываем 100 вопросов.
- **Формулировку «current job»** — в O\*NET вопросы написаны для текущего
  сотрудника, а у нас пользователь создаёт будущую или открытую вакансию.
  Поэтому переписываем:

  | Было (O\*NET) | Стало (Doki.hel) |
  |---|---|
  | How important is this to your current job? | Насколько это важно для создаваемой должности? |
  | If someone were being hired to perform this job… | Какое минимальное требование нужно указать для кандидата? |

## Модель данных

```ts
type JobProfile = {
  vacancyBasics: VacancyBasics;
  entryRequirements: EntryRequirements;
  knowledgeRequirements: KnowledgeRequirement[];
  workActivities: WorkActivity[];
  workContext: WorkContext;
  generatedVacancy?: GeneratedVacancy;
};

type VacancyBasics = {
  title: string;
  department?: string;
  location?: string;
  workFormat: "office" | "remote" | "hybrid" | "field";
  employmentType: "full_time" | "part_time" | "contract" | "temporary" | "internship";
  seniorityLevel?: "junior" | "middle" | "senior" | "lead" | "manager" | "director";
  salaryRange?: {
    min?: number;
    max?: number;
    currency?: string;
  };
};

type EntryRequirements = {
  educationLevel?: string;
  experienceRequired?: string;
  employerTrainingRequired?: string;
  onTheJobTrainingRequired?: string;
  certificationRequired?: boolean;
  certificationDetails?: string;
  apprenticeshipRequired?: boolean;
};

type KnowledgeRequirement = {
  code: string;
  name: string;
  importance:
    | "not_important"
    | "somewhat_important"
    | "important"
    | "very_important"
    | "extremely_important";
  level: 1 | 2 | 3 | 4 | 5 | 6 | 7;
  requirementType: "must_have" | "nice_to_have";
};

type WorkActivity = {
  code: string;
  name: string;
  importance:
    | "not_important"
    | "somewhat_important"
    | "important"
    | "very_important"
    | "extremely_important";
  complexity: 1 | 2 | 3 | 4 | 5 | 6 | 7;
  isCoreResponsibility: boolean;
};

type WorkContext = {
  communicationFrequency?: string;
  customerContact?: string;
  teamworkLevel?: string;
  autonomyLevel?: string;
  mistakeCriticality?: string;
  decisionImpact?: string;
  deadlineFrequency?: string;
  scheduleType?: "regular" | "irregular" | "seasonal";
  weeklyHours?: "less_than_40" | "40" | "more_than_40";
  physicalConditions?: PhysicalConditions;
};

type PhysicalConditions = {
  required: boolean;
  noiseExposure?: string;
  temperatureExposure?: string;
  contaminantsExposure?: string;
  hazardousEquipment?: string;
  protectiveEquipment?: string;
  standingWalkingSitting?: string;
  repetitiveMotion?: string;
};
```

## Мастер создания (MVP)

Не 100 вопросов, а минимальный пошаговый мастер.

**Шаг 1. Базовая информация**

```text
Название вакансии
Отдел
Локация
Формат работы
Тип занятости
Уровень должности
Зарплатная вилка
```

**Шаг 2. Требования**

```text
Какой опыт нужен?
Какое образование обязательно?
Нужны ли сертификаты?
Сколько времени нужно на ввод в должность?
```

**Шаг 3. Знания**

```text
Какие знания нужны?
Какой уровень нужен?
Что обязательно, а что будет плюсом?
```

**Шаг 4. Обязанности**

```text
Какие действия человек будет выполнять регулярно?
Какие задачи основные?
Какой уровень сложности у этих задач?
```

**Шаг 5. Контекст**

```text
С кем человек взаимодействует?
Есть ли клиенты?
Насколько самостоятельная роль?
Как часто дедлайны?
Насколько критичны ошибки?
Какой график?
Есть ли физические или опасные условия?
```

**Шаг 6. Генерация**

```text
Doki.hel создаёт:
- описание вакансии
- обязанности
- требования
- условия
- критерии отбора
- вопросы для интервью
```

## Связь с текущим мастером в продукте

Сейчас в коде уже есть диалоговый мастер (`WizardIntake` +
`lib/vacancyWizard.ts`), который детерминированно (а при включённом AI —
через `POST /api/employer/vacancy-draft`) собирает черновик вакансии. `JobProfile`
формализует и расширяет то, что мастер уже спрашивает:

| Шаг мастера сейчас (`STEPS`) | Блок `JobProfile` |
|---|---|
| `role`, `location`, `place`, `schedule`, `salaryModel`, `salary` | `vacancyBasics` |
| `experience`, `languages`, `musts`, `documents` | `entryRequirements` |
| `qualities` | `knowledgeRequirements` (мягкие/жёсткие) |
| `tasks` | `workActivities` |
| `schedule`, `dealDef` | `workContext` |

Кастомные ответы в мастере хранятся как `custom:<текст>` — та же семантика
переносится в `must_have` / `nice_to_have` профиля.

## Решение по интеграции O\*NET

**Сейчас:**

```text
Не интегрируем O*NET как внешний сервис.
Берём методологию и словарь.
Встраиваем в Doki.hel как JobProfile.
```

**Позже** (не в MVP — сначала нужен нормальный UX создания вакансии):

```text
Можно добавить O*NET occupation mapping:
- подбор похожей профессии
- автозаполнение знаний
- автозаполнение активностей
- сравнение вакансии с типовым профилем
```

## Финальная формулировка для доки

> Doki.hel использует профиль должности как основу для создания вакансии.
>
> Профиль должности включает:
> - входные требования к кандидату;
> - необходимые знания;
> - основные рабочие действия;
> - контекст и условия работы.
>
> На основе этих данных система формирует текст вакансии, обязанности,
> требования, условия, вопросы для интервью и критерии оценки кандидатов.
>
> Профиль должности не является публичной вакансией. Это внутренняя
> структурированная модель роли, из которой создаётся финальная вакансия.

**Ключевые решения:**

| Пункт | Решение |
|---|---|
| Основной термин | Профиль должности |
| Внутренний объект | `JobProfile` |
| Раздел доки | Вакансии → Создание вакансии → Профиль должности |
| Берём из O\*NET | требования, знания, рабочие действия, контекст работы |
| Не берём | обложки, сырой текст анкет, все вопросы подряд |

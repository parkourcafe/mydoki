# Автономный бэклог doki.help (Индонезия)

> Этот файл — источник правды для работы в режиме `/loop` без участия владельца.
> Агент берёт **первую незакрытую** задачу сверху, доводит её до критериев
> приёмки, проходит гейт проверки, отмечает `[x]`, коммитит и переходит к
> следующей. Если задача блокируется — помечает `[!]` с причиной и идёт дальше,
> НЕ останавливая цикл.

## Правила цикла

1. **Одна задача за итерацию.** Не браться за следующую, пока текущая не закрыта
   или не помечена `[!]`.
2. **Гейт проверки — обязателен для каждой задачи** (см. ниже). Задача не
   считается закрытой, пока гейт не зелёный.
3. **Один коммит на задачу**, сообщение описывает эффект для пользователя.
   Пушить в `claude/new-session-t23vhc` после каждой задачи.
4. **PR** — один на группу задач (см. группы), не на каждую задачу.
5. **Ветка**: перед началом новой группы — `git fetch origin claude/cool-volta-pdpl4t`
   и `git checkout -B claude/new-session-t23vhc origin/claude/cool-volta-pdpl4t`,
   если предыдущий PR смержен. Если нет — продолжать в текущей ветке.
6. **Отмечать прогресс прямо в этом файле** (`[ ]` → `[x]` / `[!]`) и включать
   правку файла в тот же коммит.
7. **Остановиться** только когда все задачи `[x]` или `[!]`, и написать итог.

### Гейт проверки (каждая задача)

```
npx tsc --noEmit        # без ошибок
npm run test:lexicon    # OK
npm run test:unit       # 96/96 или больше, без падений
npm run build           # успешно
```
Если гейт красный — чинить в той же итерации, не переходить дальше. Если после
трёх попыток не чинится — `[!]` с описанием, что именно не сходится.

## Заранее принятые решения (не спрашивать владельца)

Это ответы на вопросы, которые иначе остановили бы цикл:

| Вопрос | Решение |
|---|---|
| Сотрудник без аккаунта Doki | Вариант **B**: ослабить `employee_user_id` до nullable, добавить `employee_name`/`employee_contact`, поправить RLS. Приглашение — не делаем. |
| Лимит вакансий при закрытии | Закрывать разрешаем свободно. Лимит остаётся по активным. Антиабьюз — потом, по факту, а не превентивно. |
| Модель статусов кандидата | Главная — **доска** (`new/viewed/shortlisted/rejected/hired`). Карточка получает те же действия, стадии остаются как доп. измерение. Большой рефактор не делаем. |
| Осиротевшие файлы с русским | **Удалить** (`lib/roleTemplates.ts`, `lib/vacancyWizard.ts`, `RolePicker.tsx`, `WizardIntake.tsx`, `ShareBox.tsx`). Они без импортёров и содержат только русский. |
| Язык новых строк | Все 4 локали обязательны. Индонезийский — первым по важности, дефолт при неизвестной локали — `id`. |
| Спорная формулировка в копирайте | Выбирать более осторожную. Ничего не обещать сверх того, что подтверждается кодом. |

## Жёсткие стопы (НИКОГДА автономно)

- Не пушить в `claude/cool-volta-pdpl4t` и не мержить свои PR.
- Не делать `force push`, не переписывать чужую историю.
- Не удалять пользовательские данные, не запускать миграции против прод-базы
  (только файлы миграций в репозитории).
- Не трогать платёжную интеграцию — ценовой пилот сознательно ручной.
- Не ослаблять `tests/lexicon.mjs` и гардрейлы `lib/ai/guardrails.ts`, чтобы
  «прошли тесты». Если гард мешает — значит, неверна формулировка, а не гард.
- Не заявлять в копирайте фич, которых нет (особенно про шифрование и проверку
  подлинности документов).

## Группа 1 — механика кабинета (решений не требует)

- [ ] **1.1 Тихие сбои в трёх компонентах.**
  `CandidateActions.tsx`, `CandidateAI.tsx`, `employees/[id]/OnboardingManager.tsx`
  глотают ошибки в `run()`. Скопировать рабочий паттерн с `t.err` из
  `OffboardingManager.tsx` / `AmendmentsManager.tsx`.
  *Приёмка:* любая неуспешная операция показывает локализованное сообщение в
  4 локалях; успешная — по-прежнему молча закрывается.

- [ ] **1.2 Отклонение кандидата без подтверждения.**
  На карточке (`CandidateActions.tsx`) отклонение необратимо и без вопроса, а на
  доске есть undo. Добавить на карточку тот же undo (`revertRejection`, окно
  `UNDO_MS`).
  *Приёмка:* после отклонения на карточке появляется «Вернуть» на то же окно,
  что и на доске; истёкшее окно даёт понятное сообщение.

- [ ] **1.3 Сохранение настроек без подтверждения.**
  `app/employer/settings/page.tsx` — нет отклика на «Сохранить»; `actions.ts`
  молча выходит при пустом названии компании.
  *Приёмка:* видно «Сохранено»; пустое название даёт ошибку, а не тишину.

- [ ] **1.4 Нет выхода из формы редактирования вакансии.**
  `vacancies/[id]/edit/page.tsx` — только «Сохранить», уйти некуда.
  *Приёмка:* есть ссылка назад к вакансии.

- [ ] **1.5 Статус вакансии не виден на её странице.**
  Показывается только в списке. Добавить бейдж на `vacancies/[id]/page.tsx`.
  *Приёмка:* на карточке вакансии виден статус active/paused/closed.

- [ ] **1.6 Удалить осиротевшие файлы** (см. решение выше). Перед удалением —
  ещё раз убедиться `grep`-ом, что импортёров нет.
  *Приёмка:* файлов нет, сборка зелёная, ничего не сломалось.

- [ ] **1.7 Открыть PR группы 1** с описанием эффекта каждой правки.

# ТЗ фазы 4 — Оффбординг, внешняя верификация, семья

*Task-документ по Архитектуре v1.1 (`docs/ARCHITECTURE.md` §5 «Слой D», §7.4, §14 «Фаза 4»). Дата: 13.07.2026. Фаза 3 завершена (P3-1…P3-4).*

## 0. Границы и принципы фазы 4

**Что входит (арх. §14 «Фаза 4»):** оффбординг (процесс завершения трудовых отношений); расчёт и документы; возврат имущества; отключение доступов; архив; перенос профессиональной истории; внешние подтверждения; семейные роли и доступ.

**Ключевой принцип (§7.4):** оффбординг — это ЗАВЕРШЕНИЕ жизненного цикла одной канонической записи `Employment`, а не отдельная сущность. По завершении процесса `employment.status='ended'`, фиксируется дата последнего рабочего дня. История (онбординг, документы, изменения) сохраняется — запись переходит в архив, не удаляется.

**Рамки (как в фазах 1–3):** аддитивные миграции (общая БД с Doki.id), RLS — граница доступа, записи с состояниями/процессом — через SECURITY DEFINER RPC, 4 локали, проверка на локальном Postgres, без вердиктов/баллов, человек принимает решения; внешние подтверждения — по явному согласию субъекта.

## 2. P4-1 — модель

`employments` (аддитивно): `last_working_day date` — дата последнего рабочего дня (фиксируется при старте оффбординга).

`offboarding_tasks` (по образцу `onboarding_tasks`):
- `id`, `employment_id` (→ employments), `title`, `status` (`pending|done|skipped`), `note`, `sort`, `created_by`, `created_at`, `done_at`, `updated_at`.

RLS: чтение — через видимость employment (сотрудник + компания); запись — только компания (сотрудник read-only). Старт/завершение — SECURITY DEFINER RPC.

RPC:
- `start_offboarding(p_employment_id, p_last_working_day, p_task_titles)` — гейт `can_access_employer`; идемпотентный сид дефолтного чек-листа выхода; фиксирует `last_working_day`.
- `complete_offboarding(p_employment_id)` — гейт `can_access_employer`; `employment.status='ended'`, `end_date = coalesce(last_working_day, current_date)`.

## 3. P4-1 — экраны (4 локали)

- **`/employer/employees/[id]`** (при `status='active'`) — секция «Оффбординг»: старт (дата последнего дня), чек-лист выхода (возврат имущества, отключение доступов, финальные документы, exit-интервью) с чекбоксами, «Завершить оформление» → запись переходит в `ended`.
- **`/my/employment/[id]`** — read-only прогресс оффбординга + дата последнего рабочего дня.

## 4. P4-1 — приёмка

Работодатель стартует оффбординг (дата последнего дня) → чек-лист выхода; по «Завершить» employment переходит в `ended` с `end_date`. Человек видит прогресс. История сохраняется (архив — P4-3). RLS: чужой не видит/не трогает; запись только через RPC. typecheck/build/локальный Postgres зелёные.

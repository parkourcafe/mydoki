# ТЗ PR-2 — Напоминания: offsets + ручные (подфаза 1A)

*Task-документ по Архитектуре v1.1 и аудиту (`docs/CODE_AUDIT.md` §10). Дата: 12.07.2026.*

## 0. Контекст

Существующее: cron `/api/cron/reminders` → RPC `due_reminders()` (пороги d30/d7 захардкожены в SQL) → Resend, дедуп в `reminder_sent`. Таблица `reminders` есть, но кодом не используется. `/my/reminders` только показывает истекающие документы.

**Входит:** авто-напоминания по expires_at на настраиваемых offsets **[30,7,1]** (критерий приёмки ТЗ №1); ручные напоминания (CRUD) на существующей таблице `reminders`; email ручных напоминаний в том же cron; логика «какие пороги сегодня» — чистая TS-функция (тест с фейковым временем).

**Не входит:** SMS/push-каналы; сложное расписание; изменение сигнатуры `due_reminders()` (Doki.id использует ту же БД — старый RPC не трогаем).

**Рамки:** только аддитивные изменения (общая БД с Doki.id); RLS — граница доступа для ручных напоминаний (у `reminders` уже есть политики member/editor); строки UI — 4 локали; cron остаётся fail-closed по `CRON_SECRET`.

## 1. Модель (миграция, аддитивно)

- `reminders`: добавить `title text`, `offsets jsonb not null default '[30,7,1]'` (положительные «дней до»), `channel text not null default 'email'`. Существующие `due_at`, `message`, `done`, `document_id`, `member_id` — как есть.
- `reminder_sent_manual(reminder_id, due_on, kind, email)` — дедуп ручных напоминаний, только service_role (как `reminder_sent`).
- `due_reminder_candidates()` — новый RPC (service_role): документы с expires_at в окне [сегодня; +максимальный offset], + email членов семьи. **Без вычисления kind и без дедупа** — это делает cron в TS.
- `due_manual_reminder_candidates()` — новый RPC (service_role): не завершённые `reminders` с `due_at` в окне, + email.
- `due_reminders()` не изменяется (deprecated).

## 2. Чистая логика (`lib/reminders.ts`, unit-тест с фейковым «сегодня»)

- `parseOffsets(input): number[]` — из строки «30, 7, 1» → отсортированный уникальный список положительных целых; пусто → дефолт [30,7,1].
- `bucketKind(targetDate, today, offsets): string | null` — сколько дней до цели; вернуть метку самого срочного достигнутого порога (`d30`/`d7`/`d1` = «d»+offset), либо null если до цели дальше максимального offset или дата прошла. Обобщение текущего `case when <=7 then d7 else d30` c добавлением d1.

## 3. Cron (переписать поверх)

Для документов и ручных напоминаний: взять кандидатов из новых RPC → для каждого посчитать `bucketKind` (offsets документа = дефолт [30,7,1]; ручного = его `offsets`) → отфильтровать уже отправленные (`reminder_sent` / `reminder_sent_manual`) → сгруппировать по email → отправить дайджест → записать отправку. Fail-closed и Resend-проверки — как есть.

## 4. UI `/my/reminders` (4 локали)

Оставить секцию «истекающие документы». Добавить секцию «Мои напоминания»: форма (заголовок, дата, offsets по умолчанию «30,7,1», необязательная привязка к документу), список активных и завершённых, «отметить выполненным» / «удалить».

Actions: `createReminder`, `toggleReminder`, `deleteReminderItem` (RLS через сессию).

## 5. Приёмка

1. Документ с expires_at через 30/7/1 день → `bucketKind` даёт d30/d7/d1 (unit-тест с фейковым временем).
2. Ручное напоминание создаётся, видно в списке, помечается выполненным, удаляется.
3. Cron собирает и документные, и ручные напоминания, дедуп не шлёт повторно.
4. typecheck/build зелёные; миграция обратима (rollback в шапке).

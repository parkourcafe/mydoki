# ТЗ PR-4 — Компания: настройки + участники (подфаза 1B)

*Task-документ. Дата: 12.07.2026.*

## 0. Решение по модели

v1.1 §7/§15: имена таблиц согласуются с существующими, параллельные сущности с тем же смыслом запрещены. Поэтому **не заводим отдельную `companies`** — `employer_profiles` (1:1 c user, поле `company_name`) уже и есть компания. Добавляем:
- недостающие настройки компании прямо на `employer_profiles` (аддитивно);
- `company_members` — слой мультипользовательского доступа (задел), с бэкофиллом owner.

**Реальный доступ рекрутёров** (чтение вакансий/откликов не-владельцем) требует правок RLS на общих с Doki.id таблицах → отложено до отдельной санкции. В PR-4 `company_members` — только задел + отображение владельца.

## 1. Миграция (аддитивно)

- `employer_profiles` += `retention_months int not null default 12` (срок хранения данных отклонённых — для retention-джоба PR-11), `default_consent_text text` (текст согласия отклика — для PR-6/7), `country text`.
- `company_members(employer_profile_id → employer_profiles.id, user_id, role 'owner'|'recruiter', created_at, PK(profile,user))`. RLS: владелец профиля управляет; участник читает свою строку. Бэкофилл: owner для каждого профиля.

## 2. Код

- `saveCompanySettings(formData)` — обновляет `employer_profiles` (company_name, контакты, country, retention_months, default_consent_text). Доступ — владелец (RLS).
- Страница `/employer/settings`: форма компании + retention + текст согласия; секция «Участники» (владелец; приглашение рекрутёров — позже). Ссылка «Настройки» в шапке `/employer`.

## 3. Приёмка

Владелец открывает `/employer/settings`, меняет данные компании/срок хранения/текст согласия — сохраняется; участники показывают владельца; typecheck/build зелёные; миграция обратима; общие RLS не тронуты.

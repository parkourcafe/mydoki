# 07 · MVP-дорожная карта

Порядок выбран так, чтобы как можно раньше получить рабочую базовую ценность
(«всё по человеку в одном защищённом месте»), а более сложное (AI, обмен,
семья) добавлять поверх готового и безопасного ядра.

## Этап 1 — Ядро
**Цель:** залогиниться, завести членов семьи, безопасно загрузить документы,
увидеть их по человеку.
- Auth + **2FA**.
- Члены семьи (CRUD).
- Загрузка файлов в **приватный bucket**.
- Категории документов.
- Экран профиля человека (документы по категориям).
- RLS на всех таблицах + signed URL для файлов с самого начала.

**Готово, когда:** пользователь добавляет человека, грузит паспорт, видит его
на экране профиля; никакой публичный путь к файлу не существует.

## Этап 2 — Метаданные и напоминания
**Цель:** документы становятся структурированными и «живыми».
- Метаданные: номер / даты / кем выдан, теги.
- Поиск и фильтры.
- **Напоминания о сроках** (email/push, `expires_at`).

**Готово, когда:** можно найти документ по фильтрам и получить напоминание о
скором истечении срока.

## Этап 3 — AI
**Цель:** убрать трение при вводе.
- Авто-распознавание типа документа и метаданных (`doc-classify`).
- Предложение категории при загрузке.

**Готово, когда:** при загрузке скана поля заполняются автоматически и
пользователю остаётся только подтвердить.

## Этап 4 — Обмен
**Цель:** контролируемая отправка наружу.
- Защищённые **истекающие ссылки** на один документ.
- Отзыв ссылки, водяной знак, запрет скачивания.
- **Audit log** просмотров/скачиваний/шеринга.

**Готово, когда:** можно отправить документ врачу ссылкой с TTL, отозвать её и
видеть, кто и когда открывал.

## Этап 5 — Семья и экспорт
**Цель:** расширение на семью и переносимость.
- Household: приглашения, роли (owner / editor / viewer).
- Опекунский доступ к документам ребёнка.
- Экспорт / бэкап всего архива.

**Готово, когда:** второй взрослый видит общий архив по приглашению, а владелец
может выгрузить всё одним действием.

## Сквозные требования (на всех этапах)
- RLS включён и протестирован для каждой новой таблицы.
- Файлы — только через signed URL, никаких публичных путей.
- Каждое чувствительное действие пишется в audit log.
- Согласия (вкл. медицину) и политика — до публичного запуска (см. безопасность).

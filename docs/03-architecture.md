# 03 · Архитектура

Стек — тот же, что в PET ID, чтобы переиспользовать паттерны и опыт.

```
Next.js (App Router) + Supabase + Vercel
  ├─ Auth (email + ОБЯЗАТЕЛЬНО 2FA)
  ├─ RSC / route handlers → lib/queries → getSupabaseServer()
  ├─ Postgres + RLS (всё привязано к owner_user_id / членству в household)
  ├─ Storage: ПРИВАТНЫЙ bucket, доступ только по signed URL с коротким TTL
  └─ AI (Claude) — авто-распознавание и категоризация документов
```

## Слои

- **UI / RSC.** App Router. Кабинет пользователя `/my/*`. Серверные компоненты
  читают данные через слой запросов, не дёргая Supabase напрямую из клиента.
- **Слой запросов (`lib/queries`).** Вся работа с БД и storage инкапсулирована.
  Доступ к серверному клиенту через `getSupabaseServer()`. Клиентский bundle
  не получает service-ключей.
- **Postgres + RLS.** Авторизация — в базе. Каждая таблица защищена политиками
  RLS; приложение не может «забыть» проверку доступа.
- **Storage.** Один приватный bucket. Файлы никогда не отдаются публично —
  только через `createSignedUrl(s)` с коротким сроком жизни.
- **AI (Claude).** Пайплайн `doc-classify`: по загруженному файлу определить
  тип документа, вытащить номер/даты/кем выдан, предложить категорию.

## Переиспользуемые паттерны из PET ID

| Паттерн PET ID | Как применяем в MyDoc |
|---|---|
| `document-vault.tsx` | Экран хранилища документов члена семьи |
| Приватный bucket + `createSignedUrls` | Тот же подход, но **без** публичных QR |
| `doc-classify` (AI-классификация) | Авто-определение типа и метаданных при загрузке |
| `reminders` | Напоминания о сроках действия |
| Кабинет `/my/*` | Личный кабинет владельца аккаунта |
| RPC по образцу `get_pet_passport` | **Приватная** RPC выдачи по share-токену (см. ниже) |

## Важно: отдельный проект, а не модуль PET ID

Другой профиль риска (медицина + удостоверения), другая БД, отдельный домен.
Переиспользуем **код-паттерны и компоненты**, но:

- отдельная база данных,
- отдельный storage-bucket,
- отдельный домен и деплой,
- отдельный контур согласий и юридических документов.

## RPC выдачи по ссылке

В PET ID `get_pet_passport` отдаёт публичный профиль питомца. В MyDoc
аналогичная RPC, но:

- **приватная** — вызывается только по валидному share-токену,
- проверяет `expires_at` и `revoked_at`,
- отдаёт **один документ**, а не профиль человека,
- пишет событие в `audit_log`.

## Окружения и секреты

- Env-переменные Supabase (URL, anon key, service role) — только на сервере.
- Резидентность данных выбирается осознанно (см. безопасность и открытые вопросы).
- Бэкапы БД и storage — в плане эксплуатации.
